# Apps

Apps are the stable side of the Rudel lifecycle.

If sandboxes are where change happens, apps are where approved state lands. An app keeps domain metadata, cloned DB tables, copied active theme files, backups, deployment history, tracked Git metadata, and lifecycle policy.

An app combines:

- a Rudel environment record
- cloned WordPress tables with an app table prefix
- copied active theme files under `wp-content/rudel-apps/{app_id}/themes`
- an app record with domain metadata
- backup and deployment history

## Create an app

```bash
wp rudel app create --name=demo --domain=demo.example.test --theme=twentytwentyfour
```

The supplied primary domain becomes the app's canonical Rudel URL. Rudel stores the domain mapping in its app tables and uses it for app lookup, deploy rewrites, and operator output.

## Create a sandbox from an app

```bash
wp rudel app create-sandbox demo-1234 --name="Demo Feature"
```

That sandbox clones from the app and becomes the workspace for change work. The app stays stable while sandboxes branch off for development, QA, or experimentation.

The derived sandbox gets its own table prefix and copied theme root. Plugins, uploads, and users remain shared with the host.

If the app tracks a Git remote, branch, and directory, the derived sandbox inherits that metadata automatically:

```bash
wp rudel app create --name=demo --domain=demo.example.test --git=https://example.test/demo-theme.git --branch=release --dir=themes/demo-theme
wp rudel app create-sandbox demo-1234 --name="Demo Feature"
```

The resulting sandbox can use `wp rudel push` without repeating `--git` or `--dir`.

## Backups

Create a backup:

```bash
wp rudel app backup demo-1234 --name=baseline
```

List backups:

```bash
wp rudel app backups demo-1234
```

Restore a backup:

```bash
wp rudel app restore demo-1234 --backup=baseline --force
```

Backups capture the app's cloned tables and copied active theme files.

## Deploy

Deploys replace app state from a sandbox and record the operation.

Preview a deploy:

```bash
wp rudel app deploy demo-1234 --from=demo-feature-1234 --backup=before-deploy --dry-run
```

Run a deploy:

```bash
wp rudel app deploy demo-1234 --from=demo-feature-1234 --backup=before-deploy --label="Launch candidate" --notes="Approved by QA" --force
```

List deployments:

```bash
wp rudel app deployments demo-1234
```

Rollback a deployment:

```bash
wp rudel app rollback demo-1234 --deployment=deploy-1234 --force
```

## Domains

Apps require a primary domain value at creation time. Additional domains remain explicit mappings in Rudel's app tables.

```bash
wp rudel app domain-add demo-1234 --domain=www.demo.example.test
wp rudel app domain-remove demo-1234 --domain=www.demo.example.test
```

If you remove the current primary domain, Rudel promotes the next mapped domain and updates the app's canonical URL in the app environment tables.

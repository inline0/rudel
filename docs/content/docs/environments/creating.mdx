# Creating Environments

Creating an environment means creating a DB-backed overlay, not a WordPress multisite site.

Rudel clones WordPress tables into an environment prefix, copies the selected active theme, records runtime metadata, and leaves host plugins/uploads/users shared.

## Create a sandbox

```bash
wp rudel create --name=alpha --theme=twentytwentyfour
```

Common variations:

```bash
# clone from an existing environment
wp rudel create --name=qa --clone-from=alpha-1234

# seed from a template
wp rudel create --name=starter --template=theme-starter

# seed from a Git remote
wp rudel create --git=https://example.test/example-theme.git
```

The host database is cloned by default into a new environment table prefix. The active theme is copied into the environment-owned theme root.

## Create an app

```bash
wp rudel app create --name=demo --domain=demo.example.test --theme=twentytwentyfour
```

Apps use the same overlay runtime as sandboxes. They are durable targets with app domains, backups, deployment history, and app-derived sandbox workflows.

If an app has one long-lived Git source, capture it at creation time:

```bash
wp rudel app create --name=demo --domain=demo.example.test --git=https://example.test/demo-theme.git --branch=main --dir=themes/demo-theme
```

App-derived sandboxes inherit tracked Git metadata automatically.

## Runtime selection

Use one of the request selectors to enter an environment:

```bash
curl -H 'X-Rudel-Environment: alpha-1234' http://localhost:8000/
RUDEL_ENVIRONMENT=alpha-1234 wp option get blogname
```

If no selector is present, WordPress boots as the host.

## Policy metadata

Sandboxes and apps both support stewardship metadata:

- `--owner`
- `--labels`
- `--purpose`
- `--protected`
- `--ttl-days`
- `--expires-at`

Those values are stored in Rudel runtime records and used by cleanup, automation, reporting, and operator tooling.

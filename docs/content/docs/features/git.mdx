# Git Integration

Rudel uses Pitmaster for PHP-native Git clone, push, fetch, merge checks, and linked worktree lifecycle. It does not require the `git` binary on the host.

## Tracked theme workflows

The current overlay runtime isolates active themes. When an app tracks `themes/my-theme`, app-derived sandboxes inherit that metadata and Rudel can create a dedicated `rudel/{sandbox-id}` branch and linked worktree for the sandbox theme.

```bash
wp rudel app create --name=demo --domain=demo.example.test --git=https://example.test/my-theme.git --branch=main --dir=themes/my-theme
wp rudel app create-sandbox demo-1234 --name=feature-x
```

The sandbox records the generated branch and worktree metadata in Rudel's runtime tables.

## Push

```bash
wp rudel push feature-x-a1b2 --message="Add header template"
```

If the sandbox inherited tracked Git metadata from an app, the remote and directory are already known. You can still override them:

```bash
wp rudel push feature-x-a1b2 --git=https://example.test/my-theme.git --dir=themes/my-theme --message="Add header template"
```

## Cleanup

```bash
wp rudel cleanup --merged --dry-run
wp rudel cleanup --merged
```

Merged cleanup checks tracked branches and destroys sandboxes whose tracked work has already landed.

## Scope

Theme worktrees are first-class in the current overlay model. Plugin worktrees remain metadata-compatible, but plugins are shared with the host by default and are not isolated by the current runtime.

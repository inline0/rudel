---
title: Runtime State
description: Rudel's DB-backed source of truth.
---

Rudel runtime state is DB-backed only.

The host WordPress MySQL database contains Rudel's profile-configured metadata tables. For example, a profile might create:

- `wp_runtime_environments`
- `wp_runtime_worktrees`

Those tables are the source of truth for sandbox identity, lifecycle metadata, worktree metadata, cleanup policy, and timestamps.

## Environment records

The environments table stores:

- stable record ID
- public sandbox ID
- name and slug
- status
- path
- table prefix
- selected theme metadata
- lifecycle metadata
- clone metadata
- timestamps

## Worktree records

The worktrees table stores linked worktree metadata for Git-backed directories.

Rudel does not infer runtime state from filesystem paths. Filesystem paths are artifacts that belong to the runtime records.

## Table naming

Rudel table names derive from the active runtime profile:

```text
{wordpress_db_prefix} + {profile_table_name}
```

For a normal `wp_` installation and a profile that names its tables `runtime_environments` and `runtime_worktrees`:

```text
wp_runtime_environments
wp_runtime_worktrees
```

The profile should be stable once records exist. Renaming metadata tables after first install requires a normal database migration.

## No alternate runtime store

Rudel does not use JSON as runtime config.

Rudel does not store its metadata in SQLite.

Sandbox site data lives in cloned WordPress tables in the same host MySQL database.

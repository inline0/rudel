# Runtime State

Rudel runtime metadata is stored in host WordPress MySQL tables.

The registry tables are the source of truth for environment identity, app identity, app domains, worktrees, deployment history, and lifecycle policy. Rudel does not use JSON runtime config and does not store metadata in SQLite.

## Registry tables

Default tables:

- `wp_rudel_environments`
- `wp_rudel_apps`
- `wp_rudel_app_domains`
- `wp_rudel_worktrees`
- `wp_rudel_app_deployments`

These tables always live in the host WordPress database.

## Environment tables

Each environment has its own cloned WordPress tables with a generated prefix:

```text
wp_a4nmv7_options
wp_a4nmv7_posts
wp_a4nmv7_postmeta
```

Rudel switches the request table prefix during early bootstrap when an environment is selected. The host prefix itself remains untouched.

## Theme state

Each environment stores copied active theme files under its environment directory:

```text
wp-content/rudel-environments/{environment_id}/themes/{theme_slug}
wp-content/rudel-apps/{app_id}/themes/{theme_slug}
```

The environment record stores the selected stylesheet slug. Runtime bootstrap derives the template slug from the copied theme's `style.css`, so child themes keep a distinct parent template while still loading from the environment theme root.

## Table naming overrides

Most installs should leave the default table names alone. Advanced embedded setups can override only the Rudel portion of registry table names:

- `RUDEL_RUNTIME_TABLE_PREFIX`
- `RUDEL_RUNTIME_TABLE_ENVIRONMENTS`
- `RUDEL_RUNTIME_TABLE_APPS`
- `RUDEL_RUNTIME_TABLE_APP_DOMAINS`
- `RUDEL_RUNTIME_TABLE_WORKTREES`
- `RUDEL_RUNTIME_TABLE_APP_DEPLOYMENTS`

Define overrides before Rudel installs or bootstraps persisted runtime tables. Existing table-name changes are migrations, not runtime toggles.

Standalone connections can also set the Rudel registry prefix:

```php
$conn = new \Rudel\Connection(
    host: '127.0.0.1:3306',
    dbname: 'wordpress',
    user: 'root',
    password: 'secret',
    prefix: 'wp_',
    table_prefix: 'custom_rudel_',
);
```

That keeps the WordPress database prefix untouched and changes only Rudel registry table names.

## Service boundaries

Runtime reads and writes should go through Rudel repositories and services:

- `EnvironmentRepository`
- `AppRepository`
- `EnvironmentWorktreeRepository`
- `AppDeploymentRepository`

Environment directories are for theme files, logs, snapshots, backups, and local workspace artifacts. Runtime tables are for metadata and lifecycle state.
